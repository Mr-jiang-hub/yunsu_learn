## 1. 结论

1. **端口与实现分离**：业务层只依赖 `ObjectStorage` 端口，方法签名只出现 `String key`、`String url`、`InputStream`、`long size`、`String contentType`、`Duration ttl`，不出现任何 OSS/S3 类型。
2. **开发环境使用 S3 协议**：`storage.type=s3`，适配器为 `S3StorageAdapter`，后端连接本地 MinIO。
3. **生产环境使用阿里云 OSS**：`storage.type=oss`，适配器为 `OssStorageAdapter`。
4. **不是“改 endpoint 复用同一个实现”**：阿里云 OSS 不是 S3 协议子集，签名算法、URL 结构、SDK 行为均不同，必须是两个适配器。
5. **不拿本地磁盘当开发实现**：私有读、签名 URL、TTL 失效是 PRD 的核心行为，本地磁盘无法验证，不能把风险压到上线第一次。`storage.type=local` 只保留给单元测试/无外部依赖的 CI。
6. **生产契约不变**：`04-Q34` 仍是“服务端中转”；开发期只用端口验证 presignPut 的可行性，若改为前端直传，必须重新评审接口契约。

## 2. `ObjectStorage` 端口

### 2.1 接口定义

```java
public interface ObjectStorage {

    /** 写入对象；调用方负责生成 key、校验 MIME/魔数并传入准确大小 */
    void put(String key, InputStream stream, String contentType, long size);

    /** 删除对象；对象不存在视为成功（幂等） */
    void delete(String key);

    /** 判断对象是否存在 */
    boolean exists(String key);

    /** 生成短时下载地址；url 的 host 必须是浏览器可达的对外地址 */
    String presignGet(String key, Duration ttl);

    /** 生成短时上传地址；仅用于开发期 Q34 验证或后续直传方案 */
    String presignPut(String key, Duration ttl);

    /** 列出指定前缀下的全部对象（只读巡检用，内部按存储分页拉取） */
    List<StoredObject> list(String prefix);
}
```

`StoredObject(key, size, lastModified)` 是端口自带的只读视图，同样不暴露 SDK 类型。
`list` 只供孤儿文件巡检（04-Q47 P0）使用：调用方负责把前缀收窄到业务前缀，
本方法不做截断，桶内对象极多时由调用方限流。

### 2.2 端口约束

| 约束 | 说明 |
|---|---|
| 不暴露 SDK 类型 | 方法签名、返回值、异常均不得出现 `OSSClient`、`S3Client`、`PutObjectRequest`、`PresignedRequest` 等类型 |
| 不暴露 bucket | bucket 由配置决定，不作为业务参数；业务只关心 key |
| key 由服务端生成 | 客户端不得传入完整路径；key 的生成规则在应用层，见第 7 章 |
| 异常统一 | 适配器把厂商异常转换为 `StorageException`（运行时异常），业务层按 `50004` 处理，不向调用方泄露堆栈与厂商错误码 |
| 事务边界 | `put/delete` 不得在数据库事务内调用；先短事务落业务状态，再调用存储，结果另起短事务回写 |
| 幂等 | `delete` 对不存在的 key 返回成功；`put` 由调用方保证 key 唯一（每次上传生成新 key） |
| 资源 | `put` 不关闭调用方传入的 `InputStream`；适配器负责按 SDK 要求读取完整长度并处理流异常 |

## 3. 适配器与装配

| 实现 | `storage.type` | 使用环境 | 说明 |
|---|---|---|---|
| `S3StorageAdapter` | `s3` | 开发 | 连接 MinIO；S3 协议；支持 presignGet/presignPut |
| `OssStorageAdapter` | `oss` | 生产 | 阿里云 OSS SDK；私有 Bucket；支持签名 URL |
| `LocalStorageAdapter` | `local` | 仅单元测试 | 不参与 dev/prod 装配；不验证签名 URL 与私有读 |
| `MockStorageAdapter` | 不注册为 type | 自动化测试 | 内存实现，遵循同一端口契约 |

装配规则：

1. 由 `storage.type` 决定唯一 Bean，不允许同时装配两个真实实现。
2. `dev` Profile 默认 `s3`；`prod` Profile 只允许 `oss`；启动时校验，`prod + s3/local` 直接失败。
3. 外部依赖初始化失败不应导致应用启动即死循环重试；启动时做一次轻量校验（配置完整性 + 可选 headBucket），运行期失败按 `50004` 返回。
4. AI、短信、对象存储的厂商 SDK 只允许出现在 `integration.storage` 包内。

## 4. `S3StorageAdapter` 必须处理的四点

SDK：AWS SDK for Java v2 的 `s3` 模块（`S3Client` + `S3Presigner`）。不引入 MinIO 专有 SDK，保持实现只依赖 S3 协议，便于后续替换兼容 S3 的对象存储。

### 4.1 `forcePathStyle(true)`

MinIO 默认不支持 virtual-hosted-style。若不开 path-style，SDK/presigner 会生成 `http://bucket.minio:9000/key`，浏览器或宿主机无法解析该 host，表现为“后端能上传、前端下载 404”。

- `S3Client` 与 `S3Presigner` 都要设置 `pathStyleAccessEnabled(true)`。
- 配置项 `storage.s3.path-style` 必须为 `true`；为 `false` 时启动校验失败（MinIO 场景）。

### 4.2 内部访问地址与对外签名地址必须分开

| 配置 | 用途 | 开发示例 |
|---|---|---|
| `storage.s3.endpoint` | 后端实际读写对象（`S3Client`） | `http://127.0.0.1:9000`（后端在宿主机）或 `http://minio:9000`（后端在 compose 网络） |
| `storage.s3.public-endpoint` | 生成给浏览器使用的签名 URL（`S3Presigner`） | `http://127.0.0.1:9000` |

实现方式：

- 用 **两个配置实例**：内部 `S3Client` 绑定 `endpoint`；单独的 `S3Presigner` 绑定 `public-endpoint`。
- 不要复用客户端生成签名；签名 URL 的 host 一旦是容器内地址，前端必然无法访问。
- 若两个地址相同，也必须通过两个配置项传入，禁止在代码里写死 `127.0.0.1`。

### 4.3 `region` 固定为 `us-east-1`

MinIO 不校验 region，但 AWS SDK 的签名流程要求非空。S3 适配器固定 `us-east-1`；生产 OSS 适配器使用 OSS 自己的 region（如 `cn-hangzhou`），两者配置分开。

### 4.4 OSS 与 S3 是两个适配器

阿里云 OSS 不是 S3 协议子集：签名算法、URL 结构、上传限制与错误码均不同。禁止用“同一个 S3 实现改 endpoint”接 OSS。两者的共同点只在 `ObjectStorage` 端口契约。

## 5. `OssStorageAdapter`

- SDK：阿里云 OSS 官方 SDK（`com.aliyun.oss:aliyun-sdk-oss`）；不使用 S3 SDK。
- 私有 Bucket：`putObject` 写入；`generatePresignedUrl` 生成 GET/PUT 短时地址；不开公共读。
- 内部/对外地址：若后端使用 OSS 内网 endpoint，仍要准备一个绑定公网 endpoint 的 `OSSClient` 专门生成签名 URL；否则签名 URL 的 host 是内网地址，浏览器不可达。配置项与 S3 对称：`endpoint`、`public-endpoint`。
- `exists`：`doesObjectExist(bucket, key)`；注意其网络异常要与“不存在”区分，异常统一转 `StorageException`。
- `presignPut`：OSS 的签名 PUT **不能约束文件大小**；若签名时指定 Content-Type，客户端必须发送一致的 Content-Type。该限制写入 Q34 验证结论，不能靠“直传”替代服务端校验。
- region、bucket、密钥全部来自 `storage.oss.*`，不与 `storage.s3.*` 混用。

## 6. 配置结构

```yaml
storage:
  # local | s3 | oss
  # dev=s3（MinIO）；prod=oss（阿里云）；local 仅单元测试
  type: s3

  s3:
    endpoint: http://127.0.0.1:9000        # 后端访问
    public-endpoint: http://127.0.0.1:9000 # 浏览器签名地址
    access-key: ${STORAGE_S3_ACCESS_KEY}
    secret-key: ${STORAGE_S3_SECRET_KEY}
    bucket: yunshu
    region: us-east-1
    path-style: true

  oss:
    endpoint: https://oss-cn-hangzhou.aliyuncs.com
    public-endpoint: https://oss-cn-hangzhou.aliyuncs.com
    access-key: ${STORAGE_OSS_ACCESS_KEY}
    secret-key: ${STORAGE_OSS_SECRET_KEY}
    bucket: ${STORAGE_OSS_BUCKET}
    region: cn-hangzhou
```

校验规则：

1. `type` 只能是 `local|s3|oss`。
2. `type=s3`：`endpoint`、`public-endpoint`、`access-key`、`secret-key`、`bucket`、`region` 必填；`path-style=true`。
3. `type=oss`：`endpoint`、`public-endpoint`、`access-key`、`secret-key`、`bucket`、`region` 必填。
4. 密钥不落仓库：通过环境变量或外部配置注入；启动时缺失直接失败，不带着空配置运行。
5. `prod` Profile 禁止 `type=local` 与 `type=s3`；`dev` 默认 `type=s3`。
6. 开发环境 MinIO 连接值以仓库根目录 `docker-compose.yml` 与 `.env` 为准；后端若并入 compose 网络，只把 `endpoint` 改为 `http://minio:9000`，`public-endpoint` 不变。

## 7. 对象 key、私有读与生命周期

1. **私有 Bucket**：对象不允许公共读；无签名访问必须返回 403。签名 URL 默认 15 分钟（04-Q47）。
2. **只存 key**：数据库只存 object key，接口返回 `{key, url, expireAt}`；前端不得缓存过期 URL。
3. **key 规范**：由服务端生成，使用固定前缀便于孤儿文件巡检：
   - `avatar/{studentId}/{uuid}.{ext}`
   - `subject/{subjectId}/cover/{uuid}.{ext}`
   - `course/{courseId}/cover/{uuid}.{ext}`
4. **不允许的 key**：客户端传入的原始文件名、含 `..`/绝对路径/反斜杠的路径、空 key、超长 key。
5. **不存音频**：ASR 音频只在请求内存/流中经过，不写对象存储。
6. **不存导入原文件**：题库 xlsx 临时文件处理完即删。
7. **孤儿文件**：P0 按前缀巡检 + 人工确认（04-Q47），不自动删除可能被引用的对象；`file_asset` 表延后 P1。

## 8. Q34（直传 vs 中转）开发期验证

### 8.1 当前契约

`04-Q34` 已确认 **服务端中转**：前端 multipart 上传到后端，后端校验后写私有存储，返回 `key/url/expireAt`。本文件不改变该契约。

### 8.2 验证目的

验证 `presignPut` 在实际浏览器/HTTP 客户端下是否可用，为“未来是否改为直传”提供证据；不是现在就把上传接口改成直传。

### 8.3 验证方式

1. 在 `integration.storage` 内实现 `S3StorageAdapter`，用适配器集成测试生成 `presignPut` URL。
2. 用浏览器或 HTTP 客户端执行 PUT，再由 `presignGet` 下载并比对内容。
3. 验证：未签名 GET 返回 403；过期 URL 返回 403；path-style 下 host 为 `127.0.0.1:9000`；上传大小/类型是否可被签名约束。
4. 不在 111 个端侧接口中新增直传接口；验证代码不得进入生产 Profile。

### 8.4 结论规则

| 验证结果 | 处理 |
|---|---|
| 流程跑通，且大小/类型风险可接受 | 保留证据，后续单独评审是否把 04-Q34 改为直传；改契约必须重新确认 |
| 流程跑不通，或无法约束大小/类型导致安全不可接受 | 明确维持服务端中转，Q34 不再悬挂 |
| MinIO 通过、OSS 未验证 | 只能证明端口与流程可行；OSS 的签名 URL 需在申请到 Bucket 后单独联调，不能用 MinIO 结果替代 |

> 直接上传无法在服务端校验魔数；若采用直传，必须补“上传后校验 + 失败删除”或“仅允许受信类型/大小”的补偿链路，否则安全评审不通过。
