## 使用方式

1. **前端 mock**：以 `c-end.yaml`、`admin.yaml` 为入口，工具需支持多文件 `$ref`；按 `operationId` 生成 mock。
2. **联调 diff**：后端实现后用 springdoc 导出 OpenAPI，与本骨架比对路径、参数、必填字段、响应结构；差异回填 `04` 第 11 章。
3. **鉴权**：
   - `c-end.yaml` 根安全为 `cBearer`；注册/登录/验证码/刷新为 `security: []`。
   - `admin.yaml` 根安全为 `adminBearer`；登录/刷新为 `security: []`。
   - 两端 token 不可互用；跨端返回 401 + `20007`。
4. **统一错误**：所有业务失败 HTTP 200 + 业务 code；401/403/429/400/405/415/500/502 使用对应 HTTP 状态。通用响应见 `common.yaml`。
5. **状态变更**：只能调用 `.../enable`、`.../disable`、`.../submit`、`.../finish` 等动作接口；`PATCH`/`PUT` 不接受 `status`。
6. **幂等**：创建面试必须带 `Idempotency-Key`；其他接口的幂等载体见 `04` 第 9.5 节。

## 骨架范围与限制

- 本目录是**契约骨架**：路径、方法、关键请求体、统一响应、通用参数已给出；部分列表/CRUD 的响应内部字段以 `04` 第 6 章表格为准，未在每个 YAML 中重复展开全部示例。
- `common.yaml` 的 `ApiResponse.data` 是通用占位；具体 `data` 结构以 `04` 第 6 章为准。
- 未写入：业务实现、数据库字段、Java 类名、SQL、前端代码、原型变更。
- 未纳入：TTS（Q37 未确认）、日志导出（PRD P0 不做）、通用字典接口（不设计）。
- OpenAPI 3.1 允许 `type: [string, "null"]`；旧版 3.0 工具可能不兼容，请使用 3.1 校验器。
