## 1. 评审范围、方法与结论

### 1.1 一句话结论

**可以开工：工程初始化、数据库建库、认证与内容域可以先做；但 C-04 视频链接、C-09 改密验证码、C-05 练习续答、C-07 创建幂等这 4 个点，必须先在评审中确认补充字段/表，否则对应模块不能通过验收。**

这不是“全部无问题”的结论。决策层没有阻塞项，是因为 Q1–Q50 已按三级规则收口；实现层仍有 4 个必须落地的补充项，其中 2 个是 PRD 已有要求但 API 契约漏字段，2 个是默认方案已定但数据库还没有承载表。它们不影响“先写第一个 Controller”，但影响对应功能的完整验收。

### 1.2 评审边界

本轮只做三类动作：

1. **报告**：记录问题、位置、影响，不扩大设计。
2. **最小修正**：错别字、编号错位、断链、术语/版本不一致；逐条记录在第 12 章。
3. **回填**：把已确认结论写入 PRD、01–04、rules、V1/V2。

本轮不做：新功能、新表、新字段、新接口、Java 代码、工程初始化、原型修改、技术选型重构。需要新增的 `practice_question`、`idempotency_record` 只登记为 V5 前置，不在本轮写 DDL。

## 3. 四向追溯与数量对账

### 3.1 32 张表 vs 20 个概念实体

**结论：32 不是“20 个实体加了 12 张表”，而是 17 个实体一对一 + 3 组拆分净增 5 张 + 7 张技术支撑表。**

| 分类 | 数量 | 明细 |
|---|---:|---|
| PRD 第 8 章概念实体 | 20 | 学科、路线、阶段、课程、题目、学员、学员路线、课程进度、练习、作答、错题、维度、面试难度、面试会话、面试消息、面试报告、报告维度分、后台用户、角色、操作日志 |
| 一对一落表 | 17 | `subject`、`learning_path`、`stage`、`course`、`student`、`student_path`、`course_progress`、`practice`、`wrong_question`、`dimension`、`interview_difficulty`、`interview_session`、`interview_message`、`interview_report`、`report_dimension`、`admin_user`、`operation_log` |
| 拆分落表 | 3 组 → 8 张，净增 5 | `Question` → `question` + `question_option` + `question_scoring_point`；`Answer` → `answer` + `answer_option` + `answer_scoring_point`；`Role` → `admin_role` + `admin_role_module` |
| 技术支撑表 | 7 | `interview_quota`、`sms_send_quota`、`sms_code`、`login_failure`、`refresh_token`、`import_job`、`import_job_error` |
| **合计** | **32** | 17 + 8 + 7 = 32；等价于 25 张实体表 + 7 张支撑表 |

**7 张支撑表的依据（逐张）**：

| 表 | PRD/已确认决策依据 | 不建表会怎样 |
|---|---|---|
| `interview_quota` | PRD 5.7、PRD 13#21：每人每天 3 次，Asia/Shanghai 自然日 | 并发创建无法原子占用，可能突破 3 次；作废无法幂等返还 |
| `sms_send_quota` | PRD 13#11：60 秒限发、单号单日 10 次 | 无 Redis 时无法做跨请求频控 |
| `sms_code` | PRD 5.1/5.10、13#11：验证码 5 分钟有效、一次性 | 验证码无处持久化，重启即丢 |
| `login_failure` | PRD 5.1：连续 5 次密码错误后需改用验证码 | 无法做 C/B 端失败计数与后台 15 分钟锁定 |
| `refresh_token` | 02 §2.6、api-rules §8：Refresh 落库可撤销、刷新轮换 | 登出/改密/禁用/注销无法批量失效 |
| `import_job` | PRD 6.4：批量导入异步任务、整批结果 | 无任务状态，前端无法轮询进度 |
| `import_job_error` | PRD 6.4：逐行失败原因 | 只能整批失败，无法给出行号与原因 |

**唯一纯关联表**：`admin_role_module`。它承载“角色—模块权限”的多对多，符合 PRD 6.8 的模块权限模型；其余表都有独立业务主键或从属关系，不是纯关联表。

**已修正的计数错误**：`03` 原 §9.1 把 `InterviewReport` 写成拆成 `interview_report` + `report_dimension`。这会让总数变成 26+7=33。实际 `ReportDimension` 是 PRD 第 8 章的独立实体（第 17 项），不是报告的子表拆分。v1.0 已把该行改为 `Role` 拆分，并在表后加说明。修正位置：`docs/design/03.数据库设计.md` §9.1（评审前 L1580）。

**没有新增实体**：7 张支撑表都只承载已确认规则或技术必需，不新增业务功能；PRD 第 8 章保持 20 个概念实体，不把支撑表塞进概念模型。原 `03` §9.4 第 1 条“PRD 补 7 张支撑表”已改为“PRD 不补，支撑表在 03 记录”。

### 3.2 111 个操作 vs 98 个唯一路径

**结论：111 − 98 = 13，全部是“同一路径两个方法”，没有重复定义、没有遗漏。**

| 端 | 操作 | 唯一路径 | 差 |
|---|---:|---:|---:|
| C 端 | 42 | 40 | 2 |
| B 端 | 69 | 58 | 11 |
| **合计** | **111** | **98** | **13** |

13 个双方法路径：

| 端 | 路径 | 方法 |
|---|---|---|
| C | `/api/v1/c/interview-sessions` | GET + POST |
| C | `/api/v1/c/students/me` | GET + PATCH |
| B | `/api/v1/admin/subjects` | GET + POST |
| B | `/api/v1/admin/subjects/{id}` | GET + PATCH |
| B | `/api/v1/admin/courses` | GET + POST |
| B | `/api/v1/admin/courses/{id}` | GET + PATCH |
| B | `/api/v1/admin/questions` | GET + POST |
| B | `/api/v1/admin/questions/{id}` | GET + PATCH |
| B | `/api/v1/admin/dimensions` | GET + POST |
| B | `/api/v1/admin/learning-paths` | GET + POST |
| B | `/api/v1/admin/learning-paths/{id}` | GET + PATCH |
| B | `/api/v1/admin/admin-users` | GET + POST |
| B | `/api/v1/admin/admin-users/{id}` | GET + PATCH |

核对方法：从 `04` 第 5 章清单提取“方法 + 路径”，得到 111 个唯一组合；按路径去重得到 98；OpenAPI `c-end.yaml` 40 路径/42 操作、`admin.yaml` 58/69，与 04 完全一致。`GET /api/v1/admin/dimensions?subjectId=` 是 04 明细表中的查询串写法，正则提取时会被误判为独立路径；按路径规范去掉查询串后仍是 `/api/v1/admin/dimensions`，不是第 99 条路径。

**103 与 8 的来源**：

- 全仓库 `/api/v1` 字符串共 103 个，其中 5 个是非端点前缀：`/api/v1/admin`、`/api/v1/admin/`、`/api/v1/c`、`/api/v1/c/`、`/api/v1/internal`。
- 103 − 5 = 98 个真实路径。
- 111 − 103 = 8 = 13 个双方法路径 − 5 个前缀字符串。
- 因此“8 个差额全是同路径多方法”这个说法不成立：**同路径多方法是 13 个，8 只是扣掉 5 个前缀后的净差**。

### 4.1 五条状态机对照

### 4.2 不可进入/不可离开的状态

| 检查 | 结论 |
|---|---|
| 不可进入 | 无。`CREATING` 由创建接口进入；`EXPIRED` 由进行中超时进入；`VOIDED` 由创建中开场失败/超时进入；`INCOMPLETE` 由提前结束或进行中 AI 失败进入；`COMPLETED` 由第 4 轮回答进入 |
| 不可离开 | `CANCELLED` 为学员终态；`COMPLETED`/`INCOMPLETE`/`EXPIRED`/`VOIDED` 为面试终态；`FINISHED`/`VOIDED` 为练习终态。均符合 PRD，不允许“复活” |
| 终态重复操作 | 重复提交返回首次结果或业务码，不改变状态；`interview_session` 用条件更新，重复作废不二次返还；`practice` 重复 submit 返回首次结果 |
| 报告状态 | `COMPLETED`/`INCOMPLETE` 才允许读报告；`EXPIRED`/`VOIDED` 无正式报告；报告未生成返回“生成中”，不是状态错误 |

### 4.3 作废、过期、未完成与配额返还

| 场景 | 会话状态 | 配额 | 报告 | 一致性 |
|---|---|---|---|---|
| 创建中开场题失败 | `VOIDED`（1→6） | 返还 1 次；条件更新 `status=1→6` 成功才减，重复调用不二次返还 | 不生成 | PRD 5.7、03 §7.1.1、04 §6.7.3 一致 |
